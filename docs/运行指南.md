# ROS 2 主工程运行指南

从 `Control algorithms for humanoid robots` 文件夹执行。目标平台为 Ubuntu 24.04 + ROS 2 Jazzy，安装步骤见 [依赖说明](../dependencies/README.md)。板卡是经典 USB2CAN，CAN 速度为 1 Mbit/s；Windows 内的 Linux 虚拟机使用完整 USB 透传后的 Linux 设备。

1. 编辑 `config/motors.yaml` 的 `can_motor_controller_node.ros__parameters`。`motor_names` 必须与 `motors` 中实际连接的条目对应。填写设备、通道、ID、型号、机械限位、中立位置、方向、Kp/Kd 和跟随状态。浮点字段写成小数，包括 `direction: 1.0` 或 `-1.0`。删除未连接的电机名称和条目。
2. 执行 `bash scripts/build_ros2.sh`，通过 colcon 构建并安装节点、launch、配置和设备规则。自定义 ROS 安装设置 `ROS_SETUP=/实际路径/setup.bash`。使用未加载 ROS 1 的新终端。
3. 安装 `ros2_ws/src/usb2can_demo_lingzu/can/usb_can.rules` 并加载 udev。检查 `/dev/USB2CAN0`、`/dev/USB2CAN1` 的路径和权限，真实路径可在 YAML 修改。规则也安装到包的 `share/usb2can_demo_lingzu/udev`。
4. 加载 `source ros2_ws/install/setup.bash`，运行 `ros2 run joy joy_enumerate_devices`。ROS 2 `joy_node` 使用 SDL，按设备编号或名称选择，Linux 输入来自 `/dev/input/event*`。完整透传手柄并检查输入设备权限。
5. 默认启动 `bash scripts/run_ros2.sh`。另开已加载 ROS 2 工作区的终端，运行 `ros2 topic echo /joy`，核对各轴和按钮映射。默认参数 `joystick_axis: 1`；控制按钮索引为 0 使能、1 失能、2 置零、3 清故障，SDL 映射须实测。
6. 核对实际配置后执行 `bash scripts/run_ros2.sh hardware_confirmed:=true`。

选择手柄或自定义配置：

```bash
bash scripts/run_ros2.sh joystick_device_id:=1
bash scripts/run_ros2.sh 'joystick_device_name:=Xbox Wireless Controller'
bash scripts/run_ros2.sh motor_config:=/绝对路径/motors.yaml hardware_confirmed:=true
```

脚本读取源目录中的可编辑配置，修改硬件映射后重新启动即可。直接使用已安装的包时，默认读取构建时安装的配置副本；传入 `motor_config` 可使用编辑后的文件：

```bash
source ros2_ws/install/setup.bash
ros2 launch usb2can_demo_lingzu usb2can_joystick.launch.py motor_config:="$(realpath config/motors.yaml)"
```

手柄目标经过速度、加速度和 jerk 限制，其他电机保持使能时的反馈位置。方向和软件零点统一转换关节命令与反馈。失能按钮优先；使能和软件置零前发送停止并等待新停止反馈。软件置零将当前位置定义为关节 0，手柄居中后按使能恢复。独立关节动作使用 [多关节轨迹控制](多关节轨迹控制.md)，启动传入 `control_mode:=trajectory`。

逐关节标定、服务操作和带进度/结果的轨迹 Action 见 [关节标定与程序控制](关节标定与程序控制.md)。程序模式启动 `input_source:=program`，按说明持续提供 heartbeat；launch 仅在手柄模式启动手柄驱动。轨迹成功依据实际位置与速度到位，持续跟踪偏差或到位超时会报告失败并失能。

手柄以 20 Hz 重发；订阅 SensorData QoS，深度 1。输入和反馈超时默认均为 0.5 秒，实际时间驱动 200 Hz 控制循环。位置越界、故障、状态异常、缺失或过期反馈、发送失败触发失能，恢复后需重新按使能。参数为只读，修改后重新启动。

Ctrl+C/SIGTERM 只设置退出请求，正常流程停止接收线程、发送有界重试的失能命令、关闭设备和日志。控制节点或手柄进程退出时 launch 会关闭整组进程。若 USB 已断开，停止命令的送达仍需由实机保护措施保障。

日志默认位于 `logs/年月日_时分秒_进程号/motor_angle_log.csv`。`ROS_LOG_DIR` 指定日志目录，launch 的 `log_file` 可覆盖 CSV 路径。日志记录设备/通道/ID/型号、目标、实际角度、故障、状态及反馈年龄；反馈无效时状态列留空。旧 CSV 表头不匹配会要求更换文件。

默认 `hardware_confirmed=false` 禁止使能、置零和清故障，失能按钮和退出仍尝试发送停止报文。首次迁移后先验证手柄映射与反馈，再按 [验证说明](验证说明.md) 在目标机执行真实 ROS 2 构建、测试、断连和退出检查。

# 关节标定与程序控制

位置、速度和力矩接口统一使用关节坐标：

```text
joint_position = direction * (motor_position - zero_offset)
motor_position = zero_offset + direction * joint_position
joint_velocity = direction * motor_velocity
joint_torque   = direction * motor_torque
```

`direction` 为 `1.0` 或 `-1.0`，`zero_offset` 单位为电机坐标 rad。机械限位、中立位、轨迹、状态和 CSV 位置均使用关节坐标。旧版本中反向关节的轨迹使用电机坐标，迁移时应按上述公式转换已有轨迹和限位。

## 配置与标定

在 `config/motors.yaml` 配置每个关节的方向和初始 `zero_offset`。默认偏置为 0。启动读取 `calibration_file`，文件中已保存的偏置覆盖初始值；文件同时检查关节名称、设备、通道、ID、型号和方向，配置不匹配时拒绝启动。查询服务返回实际生效的方向和偏置。

软件标定需要选定关节已失能，并取得新停止反馈。把关节放到已知姿态，再调用：

```bash
ros2 service call /joint_command usb2can_demo_lingzu/srv/JointCommand \
  '{operation: calibrate, joint_names: [motor_01], positions: [0.15]}'
ros2 service call /joint_command usb2can_demo_lingzu/srv/JointCommand \
  '{operation: zero, joint_names: [motor_01], positions: []}'
ros2 service call /joint_command usb2can_demo_lingzu/srv/JointCommand \
  '{operation: status, joint_names: [motor_01], positions: []}'
```

`calibrate` 将当前位置定义为提供的已知关节角；`zero` 将当前位置定义为关节 0。两者通过软件偏置实现，标定结果写入文件后才更新有效坐标。写入失败保留原偏置。已使能关节、运动中的控制器、未知/重复名称、非法已知角度和映射后超出协议范围的请求被拒绝。

空 `joint_names` 选择所有配置关节；此时 `calibrate.positions` 按 `motor_names` 顺序填写。手柄按钮 2 执行全部关节的软件置零，重新使能需要先居中。标定文件路径建议按机器人和实验独立指定：

```bash
bash scripts/run_ros2.sh calibration_file:=/home/chenz/robot_calibration.txt
```

参数文件中的安全值仍为启动配置；运行时有效标定值通过 `status` 查询。修改接线或方向后，应重新核对标定文件。

## 程序控制服务

启动程序输入模式：

```bash
bash scripts/run_ros2.sh control_mode:=trajectory input_source:=program hardware_confirmed:=true
```

该模式由程序提供存活信号，launch 按模式选择是否启动手柄驱动。程序持续调用 `heartbeat`，收到成功响应后调用 `enable`，运行期间以低于 `input_timeout` 的间隔继续发送 heartbeat；建议 10 Hz。轨迹消息不能代替存活信号。程序停止或存活信号丢失后，控制器失能并终止当前任务。

服务 `/joint_command` 的类型为 `usb2can_demo_lingzu/srv/JointCommand`：

| operation | 含义 |
| --- | --- |
| status | 查询所选关节的位置、使能标志、方向与偏置 |
| heartbeat | 更新程序存活信号，名称与位置数组为空 |
| enable | 对所选关节请求新停止反馈，再发送运行模式和使能指令 |
| disable | 失能所选关节；受影响的轨迹返回失败，其余运动关节执行受限减速 |
| clear_fault | 停止所选关节并发送清故障指令 |
| calibrate | 为已失能关节设定已知关节坐标并保存 |
| zero | 为已失能关节设置软件零点并保存 |

除 `calibrate` 外，`positions` 为空。响应包含 `success`、`message` 和所选关节的有效状态。使能/清故障的成功响应表示指令发送完成；运行状态、反馈超时和故障继续由控制循环检查。使能、标定与清故障要求 `hardware_confirmed=true`。

轨迹中只能指定已使能关节。可先单独使能少量关节；其余关节不发送运控帧。新增使能关节应在当前动作结束或取消后进行。

## 轨迹任务和执行结果

Action `/follow_joint_trajectory` 使用标准 `control_msgs/action/FollowJointTrajectory`，提供目标标识、反馈、取消和最终结果。现有 `/joint_trajectory` topic 继续可用，系统为每条接受的 topic 轨迹分配 `topic-N` 标识。

```bash
ros2 action send_goal /follow_joint_trajectory control_msgs/action/FollowJointTrajectory \
  '{trajectory: {joint_names: [motor_01], points: [{positions: [0.2], time_from_start: {sec: 2, nanosec: 0}}]}}' --feedback
ros2 topic echo /trajectory_task
```

参数和含义：

| 参数 | 默认值 | 含义 |
| --- | --- | --- |
| motors.NAME.tracking_position_tolerance | 0.15 rad | 持续位置跟踪偏差阈值 |
| motors.NAME.tracking_velocity_tolerance | 0.5 rad/s | 持续速度跟踪偏差阈值 |
| tracking_error_timeout | 0.25 s | 连续超过跟踪阈值后的失败时限 |
| motors.NAME.goal_position_tolerance | 0.01 rad | 终点位置容差 |
| motors.NAME.goal_velocity_tolerance | 0.02 rad/s | 终点速度容差 |
| goal_settle_time | 0.1 s | 满足终点容差需连续保持的时间 |
| goal_timeout | 2.0 s | 指令轨迹结束后的到位等待期限 |

上述数值是示例，应依据负载、反馈量化精度和控制增益设定。判定容差包含协议量化步长。指令结束后进入 `settling`，只有新鲜、正常的实际反馈满足终点位置与速度容差并稳定保持后，才进入 `completed`。

持续跟踪偏差触发 `PATH_TOLERANCE_VIOLATED=-4`；到位超时触发 `GOAL_TOLERANCE_VIOLATED=-5`。两者清除轨迹并失能。故障、输入/反馈超时、退出或操作者失能也终止任务并附带具体原因。新有效轨迹替换旧任务，旧 Action 返回 ABORTED；非法新轨迹保留原有效任务。

Action 的逐关节位置/速度容差可收紧配置阈值。0 表示使用默认值，-1 表示不增加该项任务约束；配置中的基础跟踪保护及到位要求仍生效。由于没有实测加速度，正的加速度容差、MultiDOF 与 component 容差被拒绝。`goal_time_tolerance` 为 0 时使用 `goal_timeout`，指定时需覆盖稳定保持时间。

取消 Action 后先执行受限减速，确认实际停止后返回 CANCELED。若减速不可行或实际停止超时，则返回失败并失能。通过空 topic 取消正在执行的 Action 时，Action 返回 ABORTED 并说明取消原因；需要标准 CANCELED 结果时使用 Action 客户端的取消接口。

`/trajectory_task` 发布任务 ID、状态、说明、执行进度、计划时长、实际/目标位置和位置误差。进度 1 表示指令完成，仍可能处于 `settling`；以任务状态和 Action 最终结果判定成功。该 topic 用于观察最近任务；每个 Action 客户端应使用其目标结果获取可靠的终态。

接口定义参考 [ROS control_msgs 的 FollowJointTrajectory](https://github.com/ros-controls/control_msgs/blob/jazzy/control_msgs/action/FollowJointTrajectory.action)。

## 验证

离线 `ros2_motion_test` 覆盖偏差、到位期限、取消、逐关节操作、反向坐标、标定加载及写入失败。真实 ROS 服务/Action 测试使用生产节点、DDS 和测试创建的虚拟串口：

```bash
source ros2_ws/install/setup.bash
export ROS_DOMAIN_ID=42 ROS_AUTOMATIC_DISCOVERY_RANGE=LOCALHOST
python3 tests/ros2/test_program_interface.py
```

虚拟电机测试验证主机接口与状态机；负载下的跟踪精度和阈值仍需实机验收。

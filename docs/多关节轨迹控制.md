# 多关节轨迹控制

主节点支持按 `motor_names` 的名称独立控制多个关节。轨迹由本地 Ruckig 0.15.3 计算，每段内各关节同步到达。目标速度、加速度和 jerk 分别受限；机械限位校验覆盖插值曲线极值。

## 配置与启动

每个 `motors.<名称>` 必须填写 `max_velocity`（rad/s）、`max_acceleration`（rad/s²）、`max_jerk`（rad/s³）。示例值 0.5、1.0、4.0 需按装配填写；速度不能超过型号协议量程。旧配置缺少字段时在打开硬件前被拒绝。

从主工程目录执行：

```bash
bash scripts/build_ros2.sh
bash scripts/run_ros2.sh control_mode:=trajectory hardware_confirmed:=true
```

手柄按钮继续用于使能、失能、置零和清故障。使能时等待各电机的新停止反馈，从反馈位置和速度初始化；若仍有运动，先受限减速。输入存活信号由 `input_source` 选择：`joystick` 使用手柄消息，`program` 使用程序 heartbeat 服务。轨迹消息不能替代存活信号，输入或反馈超时仍会失能。程序模式与逐关节操作见 [关节标定与程序控制](关节标定与程序控制.md)。

## 发送轨迹

核对 [示例轨迹](../config/trajectory.example.yaml)，在另一个已加载工作区的终端执行：

```bash
source ros2_ws/install/setup.bash
ros2 topic pub --once /joint_trajectory trajectory_msgs/msg/JointTrajectory --stdin < config/trajectory.example.yaml
```

示例让 `motor_01` 到 0.2 rad、`motor_02` 到 -0.15 rad，再各自回到 0。关节顺序可以与配置不同，位置和导数数组按 `joint_names` 对应。单位为统一关节坐标 rad，`direction` 和 `zero_offset` 同时作用于命令、反馈与标定。

可指定部分关节，其他关节以接收时的指令位置为保持目标；若正在运动，在第一段内受限减速到该目标。新轨迹从当前指令位置、速度、加速度连续衔接并替换旧轨迹。非法轨迹被拒绝，当前有效轨迹继续运行。

支持 1～100 个点，总执行时间最多一小时。`time_from_start` 严格递增，`header.stamp` 为 0，收到后立即执行。首点可为 0 秒，但须与当前指令状态一致。未来时间戳会被拒绝。

`positions` 必须完整；`velocities`、`accelerations` 可省略，省略时该点以零速度/加速度到达，因此仅含位置的轨迹在途经点停稳。连续通过途经点需填写导数。最终点必须零速度、零加速度，以便保持；`effort` 会被拒绝。

默认 `retime_trajectory=false`，无法在指定时间满足限制的整条轨迹被拒绝。启动增加 `retime_trajectory:=true` 后，各分段时间作为最短时间，按限制延长；日志报告请求和计划时长，途经点时间可能顺延。

## 取消与状态

发送空轨迹执行受限减速并保持停止位置：

```bash
ros2 topic pub --once /joint_trajectory trajectory_msgs/msg/JointTrajectory '{joint_names: [], points: []}'
ros2 topic echo /trajectory_status
ros2 topic echo /joint_states
ros2 topic echo /commanded_joint_states
```

状态包括 `disabled`、`idle`、`running`、`stopping`、`settling` 和 `completed`。指令结束进入 `settling`；实际位置和速度满足容差并稳定保持后才报告 `completed`。持续跟踪偏差或终点等待超时触发失败与失能。任务进度、终态和标准 Action 结果见 [程序控制说明](关节标定与程序控制.md)。发布目标频率 50 Hz，过期反馈以 NaN 标记。`joint_states` 包含反馈位置、速度和力矩，`commanded_joint_states` 包含插值目标位置和速度。

失能、输入/反馈超时、反馈越界/超速、故障及发送失败会清除轨迹。重新使能保持新反馈位置，需重新发送轨迹。取消减速若会越过机械限位，也触发失能。控制循环超过 `max_control_gap`（默认 0.05 秒）会失能，避免跳过大段轨迹。

`control_mode=joystick` 时轴目标经过同一发生器，居中采用 `neutral_position`，支持不对称范围；非跟随关节保持使能时的反馈位置。

## 验证

`trajectory_test` 使用真实 Ruckig，覆盖同步、名称顺序、部分关节保持、途经点导数、轨迹替换、减速取消、重定时及曲线越界，并以 1 ms 采样验证各项运动边界。`ros2_motion_test` 使用真实控制循环和模拟 CAN 反馈验证下发、发布、断连、故障、发送失败和重新使能。

限制约束指令轨迹；实机加速度和跟踪误差仍需在实际负载与增益下测量。本机测试使用 ROS API/IO 替代实现，真实 Jazzy 的服务与 Action 集成测试使用虚拟串口，运行入口见程序控制说明；实际负载与硬件验收需另行执行。
